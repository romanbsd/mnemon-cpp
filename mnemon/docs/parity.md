# TypeScript vs Go / C++ parity

The TypeScript package is an in-process PostgreSQL library. The Go binary (and
its C++ drop-in) is a SQLite CLI. This document lists divergences that come
from those architectural choices. They are not treated as TypeScript bugs.

Live comparison numbers are generated by `npm run test:parity` into
`test/parity/out/report.{json,md}`. Agreement metrics are informational.
Release gates remain the TypeScript corpus quality checks in
`test/integration/corpus.test.ts`.

## How the comparison is run

| Constraint | Why |
|---|---|
| Embeddings disabled (`MNEMON_EMBED_ENDPOINT=http://127.0.0.1:1`) | The CLIs cannot ingest fixture vectors. A live Ollama instance on `:11434` would embed only the CLI sides. |
| Wall-clock `createdAt` | The CLIs stamp `time.Now()`. Fixture dates from `corpus.json` are used only by the TypeScript quality suite. |
| IDs remapped by content | Go/C++ allocate UUIDs; reports use corpus keys. |
| C++ is optional | Used when `MNEMON_CPP_BIN` or `build/mnemon` exists. Go is required (`MNEMON_GO_BIN` or `.cache/mnemon-go`). |

```bash
# from ./mnemon
mkdir -p .cache
go build -o .cache/mnemon-go /path/to/mnemon-go   # once
npm run db:up
npm run test:parity
```

## Architectural mismatches

### Near-duplicate policy

Go `Diff` classifies `DUPLICATE` / `UPDATE` / `CONFLICT` / `ADD`. On `UPDATE`
with token Jaccard ≥ 0.6 it **soft-deletes the existing insight** and
inserts the new one (`action: updated`).

TypeScript v1 never replaces. It skips only a conservative safe duplicate:

- token similarity > 0.90
- token sets equal after stopwords
- new length ≤ 125% of existing
- same `{not, no, never}` marks

Measured on the shared 31-memory corpus (embeddings off, wall-clock timestamps):

| Key | TypeScript | Go / C++ |
|---|---|---|
| `dark-mode-dup` | skipped (exact hash) | skipped (`DUPLICATE`) |
| `dark-mode-ext` | added | added (`UPDATE` suggested, token Jaccard < 0.6) |
| `dark-mode-neg` | added | **updated** — destroys `dark-mode` |
| `deploy-finish` | added | **updated** — destroys `deploy-start` |
| `cycle-b` | added | **updated** — destroys `cycle-a` |
| `tie-beta` | added | **updated** — destroys `tie-alpha` |

Keeping both sides is **intentionally safer**. Go auto-replaces when token
Jaccard ≥ 0.6 and the text is not classified `CONFLICT`. Its conflict list
includes `never` / `don't` / `no longer` but not the word `not`, so
"User does not prefer dark mode" replaces "User prefers dark mode". The
deploy / cycle / tie pairs share domain vocabulary the same way and are
also destroyed. TypeScript expected-hit rate on the latest no-embed run is
**91.3%** vs Go / C++ **56.5%**, largely because those four replacements
remove answers the query fixtures still ask for.

Decision agreement vs each CLI is **87.1%** (27/31). The four disagreements
are the updates above.

Latest snapshot: `test/parity/out/report.md` (regenerated by `npm run test:parity`).

### Graph expansion during recall

Both sides run a per-anchor beam with
`score + λ₁ · φ(edge, intent) · weight + λ₂ · max(0, cosine(query, neighbor))`.
TypeScript keeps neighbor scoring and cosine in PostgreSQL and prunes to the
intent beam between hops (a recursive CTE enumerates simple paths and hangs
on a dense 24h graph). Rerank still composes keyword / entity / similarity /
graph in TypeScript. Graph is min-maxed only among keyword hits and
near-duplicate cosine (≥ 0.85) so a wall-clock 24h clique cannot drown
token matches.

### Entity extraction

Both sides run `ExtractEntitiesIndexed`: regex + tech dictionary + a
known-entity fourth path (tokens already stored on active insights).

### Lifecycle

Go auto-prunes when `MNEMON_MAX_INSIGHTS` is exceeded and applies a `stored_at`
grace window. TypeScript v1 does not prune.

### `related`

| | Go / C++ | TypeScript |
|---|---|---|
| Walk | FIFO BFS | first-visit BFS in SQL (one hop per query) |
| Default cap | none | 20 (parity run uses 100) |
| Payload | `{id, depth, via_edge_type}` | `RelatedInsight` (`depth`, `viaEdgeType`) |

### Recall sort and WHY leftovers

Both sides break ties with `score, importance`. WHY leftover nodes keep the
pre-topo order. TypeScript does not auto-replace or auto-prune.

### Temporal edges

Both implementations use a `now − 24h` window. Because the parity run cannot
inject fixture timestamps, every memory is created "now" and the temporal
graph is denser than the dated TypeScript quality corpus.

### Storage and API

SQLite vs PostgreSQL/pgvector, CLI JSON vs in-process types, no `updated`
action, no `show`, no auto-replace, no auto-prune. `remember` now returns
Go's Diff `suggestion` (`ADD` / `DUPLICATE` / `UPDATE` / `CONFLICT`) and a
`diff` match list. TypeScript never applies `UPDATE` or `CONFLICT`; the
caller may `forget` the suggested id. TypeScript also exposes `search`
(token overlap + English FTS), `list` (recency browse), `log`, and `status`. FTS is a browse signal
only; recall anchors stay keyword / vector / time so the dated quality
corpus does not regress. These are product choices, not porting defects.

## Latest no-embed comparison (2026-09-02)

| Metric | vs Go | vs C++ |
|---|---|---|
| Decision agreement | 87.1% | 87.1% |
| Edge Jaccard | 56.9% | 56.9% |
| Mean top-5 key overlap | 54.7% | 53.3% |
| Expected-hit (rank bound) | TS 91.3% / Go 56.5% | TS 91.3% / C++ 56.5% |

Most extra TypeScript edges are temporal: the CLI sides have four fewer live
nodes after auto-replace, so their 24h proximity graphs are smaller. Residual
rank drift is graph-membership and tie-break, not a TypeScript safety failure.

The TypeScript quality suite with fixture embeddings and dates still requires
≥90% expected keys in the top 5 and keeps every extension and negation.

Both sides used local Ollama `nomic-embed-text` at `http://127.0.0.1:11434`
via `/api/embed` (no nomic prefixes). C++ was not in this run.

| Metric | vs Go |
|---|---|

| Edge Jaccard | 66.3% |
| Mean top-5 key overlap | 65.3% |
| Expected-hit (rank bound) | TS 100% / Go 78.3% |

The same four keys still disagree, but embeddings change Go's action from
`updated` to **`skipped` (`DUPLICATE`)**: cosine ≥ 0.9 on same-domain text
makes Go drop `dark-mode-neg`, `deploy-finish`, `cycle-b`, and `tie-beta`
without storing them. TypeScript still adds all four. That is why those
keys are absent from Go recall (`not-discard-negation`, `when-deploy`,
`causal-cycle`, `tie-query`).

No harmful TypeScript mismatches. Snapshot: `test/parity/out/report-embed.md`.

## What *is* a TypeScript bug

Fix (and add a regression) when the TypeScript side:

- skips an extension or a negated correction
- fails to skip an exact normalized duplicate
- returns a soft-deleted insight from `recall` / `related` / `get` / `search`
- crashes or errors on the shared corpus
- disagrees with itself across two identical recalls

Do not "fix" TypeScript toward Go auto-replace or unbounded BFS without a
failing quality or safety fixture.
